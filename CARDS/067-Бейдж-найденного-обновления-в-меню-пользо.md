## Задача
UX-пробел, подтверждённый живым прогоном (duopulse-065, 01.11.2026).
Механизм автообновления исправен: тихая автопроверка на старте (~20 с,
updater.autoCheck) находит новую версию, страница «Настройки → Обновления»
показывает «Доступна версия X» и кнопку «Установить X и перезапустить».
Но обновление лишь запоминается (pending) — снаружи о нём никто не
сообщает: ни в меню «⋮» (пункт «Проверить обновления…» просто ведёт в
настройки), ни в хроме. Пользователь, не заходящий в настройки, не узнает
о выходе версии (жалобы «автообновление не работает» отчасти отсюда).

Решение (направление): индикатор на кнопке «⋮» (точка/цифра версии) при
наличии pending-обновления — по итогам автопроверки и ручных проверок
(updater.status().pending / событие после check). Клик по пункту меню
«Проверить обновления…» уже открывает раздел — достаточно. После установки
или «у вас последняя версия» индикатор гаснет. Стиль — как у существующих
бейджей хрома (duo-кнопка с count, гайд 06 §5).

## Критерии готовности
- [x] После автопроверки с available=true на кнопке «⋮» виден индикатор
      (живая проверка или e2e: локальный фид с фиктивной версией)
- [x] Индикатор не появляется при «у вас последняя версия» и при ошибке сети
- [x] После установки (или исчезновения pending) индикатор гаснет
- [x] Витест на логику показа/скрытия индикатора
- [x] vitest зелёный; CHANGELOG дополнен
