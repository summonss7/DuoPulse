## Задача
Дефект юзабилити основного сценария, найден живым прогоном при комплексной
проверке (карточка duopulse-065, 01.11.2026). На свежем профиле (или первом
видео) субтитры приходят в состоянии «enabled=true, набор пуст» — stdio:
`[subtitles] set-state: вкл — 0 дорожек (via video)`. В этом состоянии:

- Alt+D (subtitles.toggle) **выключает** показ (`set-state: выкл — via alt-d`),
  хотя docs и код декларируют «на пустом наборе включение собирает дефолт
  „оригинал + ru“» — дефолт не собирается, потому что флаг уже поднят;
- кнопка duo выглядит включённой (aria-pressed=true), оверлея нет — пользователь
  не понимает, что нужно открыть панель и нажать чип «Дуо en+ru».

При этом сам путь через панель работает (живой прогон: чип «Дуо en+ru» →
`set-state: вкл — 2 дорожек (via select)`, оверлей рисуется, смена цветов
живая). Значит, чинить нужно именно дежурный путь включения.

Решение (направление): в content-слое (duopulse-content / применение
set-defaults) обрабатывать состояние «enabled && набор пуст && дорожки
доступны» — собирать дефолт defaultSetIds(...) вместо простого снятия флага:
и при Alt+D (переход вкл на пустом наборе), и при восстановлении «via video»
пустого набора (либо не поднимать флаг enabled, либо сразу собрать дефолт —
выбрать по docs/03 §8 п.2 «последний набор»). Сценарий: лекция на английском →
Alt+D → дуо «оригинал + ru» (docs/01 §5.1) должен работать с первого нажатия.

## Критерии готовности
- [ ] На свежем профиле Alt+D на видео с дорожками включает дуо-набор
      «оригинал + перевод» с первого нажатия, оверлей появляется без ручного
      выбора в панели (живая проверка или e2e)
- [ ] Повторный Alt+D выключает показ; набор помнится (docs/03 §8 п.2)
- [ ] Юнит-тест content-слоя на сценарий «enabled=true + пустой набор +
      tracks_ready» (сбор дефолта, а не снятие флага)
- [ ] Установленный набор виден в duo-панели сразу (чип подсвечен)
- [ ] vitest и cargo зелёные; CHANGELOG дополнен
