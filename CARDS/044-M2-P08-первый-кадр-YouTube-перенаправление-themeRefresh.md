## Задача
Метрика P-08 (docs/04 §2): «время до первого кадра видео (повторный просмотр)
≤ Chrome+uBO (не хуже)» — на gate M2 НЕ достигнута: медиана DuoPulse 5,9–8,7 с
против стабильных ~4,1–4,4 с у чистого Chrome (e2e/perf/p08.mjs, 2 сессии
замеров 16.10, релизная сборка; прогоны DuoPulse 2,5–18,4 с — большой разброс,
Chrome ровный; реклама в DuoPulse не показана ни разу — скриптлеты работают).

Собранные факты (трейсы CDP, e2e/perf/p08.mjs + инструментированные прогоны):
- При старте watch-страницы видео почти стартует (~2,3 с, readyState 4),
  затем на ~2,7 с документ ПЕРЕЗАГРУЖАЕТСЯ на тот же URL с добавкой
  `&themeRefresh=1` (виден в логе инъекций: content script injected →
  about:blank ×2 → …/watch?v=…&themeRefresh=1), после перезагрузки первый
  кадр контента на ~8,6 с. Быстрые прогоны (~2,5 с) — обходятся без
  перезагрузки.
- Гипотеза (проверить): YouTube каждый запуск повторяет themeRefresh-флоу
  (установка PREF/тема-куки) — вероятно, запрос установки или сама кука
  режется списками (EasyList/uBO) либо не переживает профиль, и перенаправ
  происходит в каждом сеансе; Chrome чистый проходит флоу один раз
  (прогрев 7,3 с → далее ровно ~4,4 с).
- Сопутствующий шум в консоли страницы: «JSON error: missing field `cmd`»
  (источник не установлен; наши content-скрипты строку не логируют —
  проверить scriptlet-набор и саму страницу).

Задача: найти причину повторного themeRefresh-перенаправа/перезагрузки
(сеть-правила? куки? scriptlet?) и довести P-08 до «не хуже Chrome» на
e2e/perf/p08.mjs (3+3 прогона, медианы).
