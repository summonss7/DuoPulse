## Задача
Обнаружено при прогоне в карточке duopulse-048 (22.10.2026): стенд
e2e/proxy-a/run.mjs падает 11/26 проверок ЕЩЁ ДО правок 048 (проверено на
бейзлайне: git stash правок → тот же результат). CI (ci.yml) гоняет только
e2e/vpn — поломка не ловилась.

Симптомы (оба прогона, baseline и 048):
- «статус в меню — ВКЛ» — state=off при включённом и работающем прокси
  (CONNECT-лог до этого полон: WebView2 → роутер → SOCKS5-стенд);
- «настройки прочитаны в форму» — пустые дефолты (host="", port=1080),
  как будто refresh() меню не выполнялся (меню не открывается?);
- «тумблер сохранил выключение в settings.json» — нет;
- далее каскад: off/on-переключения, пароль RFC 1929, fail-closed
  (REP≠0 — probe rep=0, роутер принимает!), перезапуск.

Последний полный зелёный прогон — задача 6.1 (26/26, 20.10.2026, CHANGELOG).
С тех пор менялись: панель VPN + bridge v10 (6.5, duopulse-041), страница
ошибки (048; правки стенда fail-closed-страницы на новую duopulse://error
уже внесены в run.mjs — но само меню сломано раньше по сценарию).

Вероятные места: src/proxy-menu.ts (открытие меню/refresh/статус),
bridge vpn.status → state для прокси-режима, id элементов меню; и/или
взаимодействие меню с панелью VPN (6.5). Отдельно решить: включить
e2e/proxy-a в CI (отдельная джоба или в существующую), чтобы не
протухал.
