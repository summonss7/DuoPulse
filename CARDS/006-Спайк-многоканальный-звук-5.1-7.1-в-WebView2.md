## Задача
Пожелание автора (карточка duopulse-004): звук обязан играть на системах 5.1 и 7.1 —
это требование F-11 (docs/01 §4.1). Спайк M0 (duopulse-003) звуковые каналы не проверял.
Нужно на реальной системе 5.1/7.1 убедиться, что WebView2 воспроизводит многоканальные
дорожки без молчаливого сведения к стерео, и зафиксировать результат протоколом
(задача 1.7 этапа M1, docs/05 §3).

Порядок проверки:
1. Настроить устройство вывода Windows на 5.1, затем на 7.1 (панель управления звуком,
   настроить динамики, поканальный тест ОС должен проходить — иначе проблема ниже уровня браузера).
2. В спайке M0 (`npm run tauri dev`) открыть локальный HTML с поканальными
   аудио/видео-тестами (PCM/WAV/MP4 с голосовой меткой каждого канала: Front Left,
   Center, Rear Right и т.д.) — воспроизведение через `<audio>`, `<video>` и WebAudio.
3. Открыть YouTube-ролики с дорожкой 5.1 (тест-ролики «5.1 surround test») — сравнить
   с Chrome/Edge на той же машине.
4. Результаты (конфигурация драйвера/ОС, что звучит и из какого динамика, сравнение
   с браузерами) оформить в e2e/m0-results/AUDIO-PROTOCOL.md; вывод: подтверждено /
   нужны флаги WebView2 / блокер.

## Критерии готовности
- [ ] Устройство вывода проверено в режимах 5.1 и 7.1 (собственный тест ОС проходит) — **блокер**: на машине нет устройства вывода 5.1/7.1 (Realtek = стерео-динамики ноутбука, NVIDIA HDMI без подключённого ТВ/ресивера; WASAPI-микс и PhysicalSpeakers — 2 канала, mask 0x3)
- [ ] Поканальный тест в спайке: каждый канал звучит отдельно и из правильного динамика (через `<audio>`/`<video>`; WebAudio — отдельно) — программная часть выполнена: 6/8 каналов дискретны, утечек нет (AUTO-TEST PASS 7/8, WebAudio отдельно); «из правильного динамика» — требует колонок 5.1/7.1, отложено вместе с п.1
- [x] YouTube 5.1-видео в спайке звучит не хуже, чем в Chrome/Edge на той же машине — подтверждено: поведение идентично Edge (web-плеер YouTube сам выбирает стерео-дорожку; 6ch-форматы в манифесте лежат, но не выбираются — политика платформы для web-клиентов)
- [x] Протокол e2e/m0-results/AUDIO-PROTOCOL.md заполнен (конфигурация, результаты, вывод)
- [x] Вывод зафиксирован в ROADMAP.md («Изменения плана»): подтверждено программно / блокер на железе
- [x] Отчёт в promt.txt, коммит и пуш
