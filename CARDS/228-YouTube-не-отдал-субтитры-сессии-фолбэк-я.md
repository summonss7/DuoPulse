## Задача
Диагноз duopulse-226: YouTube изредка отдаёт деградированной анонимной сессии watch-ответ
без секции captions (видео субтитры имеет — проверено свежим анонимным fetch; перезагрузка
страницы не помогает — куки сессии живы, рестарт браузера ротирует сессию и лечит).
Сейчас десктоп читает список дорожек ТОЛЬКО из player-ответа страницы (movie_player →
ytInitialPlayerResponse → TextTrack) — в такой сессии DuoPulse бессилен до рестарта.

Сделать устойчивость:
1. Фолбэк ядром (desktop): если player-ответ страницы без captions (и это не Shorts-заглушка),
   ядро запрашивает player innertube-клиентом (аналог мобильного duo_yt_player; клиент
   ANDROID/TV отдаёт captionTracks и timedtext baseUrl, работающий без PO-токена — так
   грузит yt-dlp) и отдаёт дорожки в движок.
2. Тело дорожки из фолбэк-ответа качать напрямую (без программирования плеера страницы);
   переводы — существующим путём (tlang к живому URL не подходит — подпись; использовать
   перевод gtx/прогрессивный показ как сейчас).
3. В панели/диагностике различать «у видео нет субтитров» и «YouTube не отдал их сессии»
   (журналировать факт пустого playerCaptionsTracklistRenderer при живом videoDetails).

## Критерии готовности
- [ ] Ядро desktop умеет запрашивать player-ответ innertube-клиентом и извлекать captionTracks (+ unit-тесты на разбор)
- [ ] Фолбэк включается ТОЛЬКО при пустых captions страницевого ответа; обычный путь не меняется (регресс на живом YouTube: дорожки как раньше)
- [ ] Тело базовой дорожки по baseUrl фолбэк-ответа грузится без PO-токена — проверено на живом YouTube (cues > 0)
- [ ] Панель/диагностика различает «нет субтитров у видео» и «сессия без captions»; вторая показывает внятный статус
- [ ] Тесты прогнаны (npm run test / cargo test), сборка без предупреждений; CHANGELOG дополнен; коммит + push в том же сеансе
