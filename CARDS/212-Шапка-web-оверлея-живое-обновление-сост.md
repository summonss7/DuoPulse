## Задача
Найдено при duopulse-210. Состав ряда 1 шапки web-оверлея (кнопка вкладок
с бейджем, «⬇», щит VPN) синхронизируется хуком __duopulseHeaderState в
syncChrome — то есть только на смене URL/открытии/показе оверлея. Пока
оверлей открыт, состояние старта может измениться (закрылась фоновая
вкладка → бейдж врёт; поднялся/упал тоннель → щит опаздывает) — шапка
«зеркало старта» расходится с оригиналом до следующей смены адреса.

Сделать событийную подписку: tabs.ts/vpn.ts уведомляют Kotlin (или Kotlin
переопрашивает хук по событию postMessage/evaluateJavascript-каналу) при
изменении count/видимости щита, оверлей обновляет бейдж/щит/«⬇» без смены
URL. Дешёвая альтернатива — переопрос хука раз в ~3 с, пока оверлей виден.

## Критерии готовности
- [x] При открытой вкладке видео и открытом оверлее закрытие видео-вкладки
      (из листа вкладок или плеера) убирает «⬇» из шапки оверлея без смены
      его адреса
- [x] Бейдж-счётчик вкладок в шапке оверлея меняется при закрытии/открытии
      вкладок, пока оверлей открыт
- [x] Щит VPN появляется/исчезает при включении/выключении тоннеля, пока
      оверлей открыт
- [x] Пустых переопросов нет при спрятанном оверлее (не жжём батарею)
- [x] vitest/tsc чисты, живой прогон на эмуляторе описан в CHANGELOG
