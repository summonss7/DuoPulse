## Задача
Реализовать первый инкремент VPN-подсистемы (F-12, дизайн — docs/02 §6.3 «A»):
поддержка внешнего прокси SOCKS5/HTTP(S) — чтобы уже с имеющимся прокси/VPN-клиентом
(с локальным портом) открывать заблокированные сайты из самого браузера, без
отдельного системного VPN-приложения на каждый случай.

Что входит (задача 1.8 в docs/05 §3, этап M1):

- Настройки прокси: тип (SOCKS5/HTTP/HTTPS), адрес, порт, логин/пароль.
- Применение через аргументы окружения WebView2 (`--proxy-server`,
  `--proxy-bypass-list` для локальных адресов), применение с перезапуском
  приложения (перезапуск предлагается явно).
- Тумблер и статус в меню (вкл/выкл; ошибка соединения — сигнальный цвет
  по гайду 06 §2).
- Пароль прокси — в DPAPI/credential store, не в settings.json.
- Полный WireGuard-клиент НЕ входит — это этап M6 (задачи 6.1–6.6).

## Критерии готовности
- [ ] Настройки прокси (тип/адрес/порт/логин/пароль) редактируются в UI; пароль хранится в DPAPI, не в settings.json
- [ ] Тумблер «Прокси» в меню + статус (вкл/выкл/ошибка) в фирменном стиле (гайд 06)
- [ ] С включённым прокси браузер открывает сайт, недоступный напрямую; проверка IP-эхом показывает адрес прокси
- [ ] С выключенным прокси все соединения прямые; localhost/локальные адреса никогда не идут через прокси
- [ ] Применение настроек с перезапуском работает без ручных правок конфигов
- [ ] Тесты/сборка прогнаны, результат описан; CHANGELOG-запись с датой и временем начала и окончания работы
- [ ] Коммит с осмысленным сообщением и push
- [ ] Документация актуализирована (docs/05 §3 задача 1.8 — отмечена выполненной; README — если формулировки изменятся)
