## Задача
Этап 4 цепочки duopulse-106. Вход в аккаунт Aila в DuoPulse (десктоп) и синхронизация
паролей между компьютерами:

- Экран/раздел «Аккаунт Aila» в настройках: вход (username + пароль; PBKDF2-клиент
  как в Aila: /api/login/params → auth_hash/wrap_key), статус (кто вошёл, выход),
  сессия хранится в профиле. Без входа всё работает локально (этапы 1–2).
- Ключ синка: HKDF(wrap_key, info=«duopulse passwords») — локальный DPAPI-ключ хранилища
  при входе мигрируется/оборачивается под аккаунт; при смене пароля Aila — повторный вход.
- Синхронизация: vault паролей (шифрованный блоб) через appdata (этап 3), push/pull
  по кнопке и автоматически (при старте/после изменений, с бэкоффом); merge — по
  origin+username, конфликт пароля на одном сайте — последний updated_at выигрывает,
  проигравший сохраняется отдельной записью-дублем не молча.
- Локальные пароли, накопленные до входа, при первом входе вливаются в облако.

## Критерии готовности
- [ ] Вход/выход аккаунта Aila работает; состояние «без аккаунта» не ломает локальное
      использование (этапы 1–2 работают без входа)
- [ ] Пароль, сохранённый на одной машине, появляется на другой после синка; локальные
      пароли до входа попадают в облако при первом входе
- [ ] Блоб на сервере шифрованный (руками по БД Aila видно только ciphertext)
- [ ] Смена пароля/выход не теряет локальные данные; cargo/vitest/typecheck зелёные,
      живая проверка входа описана
- [ ] CHANGELOG, README, коммит + push
