# 02 · Архитектура и выбор стека

## 1. Общая схема

Продукт разделён на четыре слоя с жёсткими границами. Ключевое правило: **слой,
реализующий ценность (субтитры, блокировка, UI), не знает, на каком движке работает**.

```
┌─────────────────────────────────────────────────────────────┐
│  UI-слой (Svelte + TypeScript)                               │
│  хром браузера: таб-бар, omnibox, меню, настройки,           │
│  панель субтитров, страница «Новая вкладка»                  │
├─────────────────────────────────────────────────────────────┤
│  Content-слой (TypeScript, инжектируется в страницы)         │
│  детектор <video>, адаптеры платформ (YouTube…),             │
│  движок cue-таймлайна, оверлей субтитров                     │
├─────────────────────────────────────────────────────────────┤
│  Core-слой (Rust)                                            │
│  менеджер вкладок, блокировщик запросов (adblock-rs),       │
│  парсеры субтитров, кэш переводов (SQLite), настройки        │
├─────────────────────────────────────────────────────────────┤
│  Shell-слой (заменяемый): Tauri 2 + WebView2                 │
│  окно, webview-процессы, инжекция скриптов, перехват сети   │
│  (fallback: Electron + Chromium — тот же контракт)           │
└─────────────────────────────────────────────────────────────┘
        ↑ IPC-контракт (bridge): команды + события, JSON-схемы
```

UI и Content общаются с Core только через типизированный IPC-контракт (`bridge/`).
Это позволяет заменить Shell-слой (Tauri → Electron) без переписывания ценностных слоёв.

## 2. Выбор Shell-слоя: почему Tauri 2 (основной путь)

| Критерий (приоритеты пользователя) | Tauri 2 + WebView2 | Electron | CEF (C++) | Fork Chromium |
|---|---|---|---|---|
| Скорость запуска / RAM | **лучший** (нативное окно, общий WebView2-рантайм) | средний (свой Chromium, ~200 МБ) | хороший | хороший |
| Размер дистрибутива | **~10–20 МБ** | ~100–200 МБ | средний | огромный |
| DRM (Widevine) | риск: поддержка в WebView2 ограничена | **есть** | есть | есть |
| Расширения Chrome | экспериментально (не критично: своё инжектим) | **есть** | есть | есть |
| Скорость разработки | высокая (Rust + любой фронтенд) | **очень высокая** | низкая | очень низкая |
| Возможности сетевого перехвата/блокировки | **Rust-стек: adblock-rs (движок Brave)** | node-стек, медленнее | C++ | максимум |

Решение: **основной путь — Tauri 2** (приоритет №1 пользователя — скорость), с
обязательным спайком M0 и заранее подготовленным fallback на Electron. DRM-риск
ограничен: большинство YouTube-видео воспроизводится через HTML5 MSE без Widevine;
под ударом только премиум/музыкальный контент (см. ROADMAP «Риски»).

Отдельно про звук (требование F-11, 5.1/7.1): аудиостек у всех трёх Chromium-вариантов
один и тот же (вывод через WASAPI), т.е. выбор оболочки на многоканальный звук не
влияет — но фактический вывод проверяется спайком duopulse-006 на реальной системе
5.1/7.1 (задача 1.7 этапа M1), потому что конфигурация драйвера/ОС может сводить звук
к стерео на любом из них.

## 3. Компоненты Core (Rust)

| Модуль | Ответственность | Библиотеки |
|---|---|---|
| `tabs` | жизненный цикл вкладок webview, спящий режим (throttle) | tauri 2 APIs |
| `adblock` | фильтрация запросов/косметика, списки EasyList+uBO, вкл/выкл по сайту | `adblock-rs` |
| `subtitles` | парсеры SRT/VTT/YouTube-timedtext; хранение cue-таблиц | `nom`/ручные парсеры, `rusqlite` |
| `translate` | клиенты провайдеров, батчинг, кэш (SQLite), деградация офлайн | `reqwest` |
| `history` | история/закладки, полнотекстовый поиск | `rusqlite` FTS5 |
| `settings` | настройки профиля, миграции схем | JSON + версии |

## 4. Компоненты Content-слоя (инжектируемый TS)

В WebView2 скрипт `duopulse-content.js` добавляется через
`AddScriptToExecuteOnDocumentCreatedAsync` — выполняется на каждой странице до её
скриптов. Внутри — компактный рантайм без зависимостей (сборка в один IIFE-бандл):

- `detector` — MutationObserver + `document.querySelectorAll('video')`;
- `adapters/` — платформенные стратегии получения дорожек (см. 03-dual-subtitles);
- `engine/` — cue-таймлайн, синхронизация с `video.currentTime`;
- `overlay/` — рендер строк субтитров набора, 1–3 одновременно (DOM поверх видео, `pointer-events:none`);
- `messaging` — канал до Core (настройки, команды включения, готовность треков).

## 5. Поток данных двойных субтитров (кратко)

```
страница YouTube загружена
  → content: детектор находит <video>, адаптер YouTube читает список дорожек
    (caption tracks, которые плеер сам получил)
  → пользователь включает субтитры (клавиша/кнопка): выбирает набор из 2–3 дорожек
    (базовый случай: оригинал + перевод)
  → Core: грузит cue-таблицы всех дорожек набора, при необходимости перевод (M4, кэш)
  → content engine: на timeupdate ищет активные cue всех дорожек набора
  → overlay: рисует строки набора в фирменном стиле
```

Полный дизайн — [03-dual-subtitles.md](03-dual-subtitles.md).

## 6. План «смены движка» (fallback Tauri → Electron)

Контракт `bridge/` фиксирует: команды (`subtitles.enable`, `adblock.set_enabled`,
`tabs.*`, `history.search`, …) и события (`page.video_detected`, `subtitles.tracks_ready`,
…). При переходе на Electron реализуется только новый адаптер IPC (electron-ipc вместо
tauri-ipc); UI, Content-слой и Rust-библиотеки переиспользуются (Rust компилируется в
Node-модуль через `napi-rs`). Триггеры перехода — провал gate M0.

## 7. Хранение данных

- Профиль пользователя: `%APPDATA%\DuoPulse\profile\`
  - `duopulse.db` (SQLite): история, закладки, кэш переводов, метаданные субтитров;
  - `settings.json` (+ автоматический бэкап предыдущей версии);
  - `filters/` — локальные копии блок-листов с датой обновления.

## 8. Безопасность

- CSP для собственных страниц UI; инжектируемый код подписан сборкой.
- Remote-контент исполняется в песочнице webview (как в обычном браузере).
- Провайдеру перевода отправляется только текст субтитров, не содержимое страниц;
  ключи хранятся в DPAPI/credential store, не в settings.json.
- Блок-листы обновляются по HTTPS с фиксированным набором источников.

## 9. Тестирование (влияние на архитектуру)

- Rust: unit-тесты парсеров (SRT/VTT/timedtext фикстуры), интеграционные тесты кэша.
- Content: запуск движка в jsdom/headless-тестах на записанных DOM-фикстурах YouTube
  (защита от «YouTube поменял DOM»).
- E2E: минималистичный драйвер поверх WebView2 ( WebDriver / Playwright при переходе
  на Electron) — прогон «10 случайных видео с двойными субтитрами».
