# 03 · Дизайн двойных субтитров

Главная фича DuoPulse. Формулировка цели: **на любом видео — несколько синхронных
строк (2–3 и больше): оригинал и переводы в любых комбинациях языков; выглядит
нативно, не тормозит, не ломается от смены качества видео.** Базовый случай —
двойные субтитры «оригинал + перевод» (имя продукта от него); расширенный — набор
из трёх и более дорожек по выбору пользователя.

## 1. Терминология

- **Cue** — единица субтитра: `{start, end, text}`.
- **Дорожка (track)** — упорядоченный список cue + язык + источник.
- **Адаптер** — стратегия получения дорожек для конкретной платформы.
- **Оверлей** — DOM-слой DuoPulse поверх видео, где рисуются субтитры.
- **Набор (стек) дорожек** — упорядоченный список дорожек, показываемых вместе:
  от 1 до 3 в UI v1 (архитектурного верхнего предела нет). Базовый случай — пара
  «оригинал + перевод»; расширенный — например `en + ru + es` или
  «оригинал + перевод платформы + свой файл». Порядок дорожек в наборе задаёт
  порядок строк на плашке.

## 2. Принцип: рендерим сами, нативные субтитры гасим

Платформенные субтитры (YouTube-плеер) мы **не используем для отображения**. Вместо
этого адаптер получает cue-данные, а наш оверлей рисует все строки набора. Так мы полностью
контролируем вид, позицию, тайминги и не зависим от стилей плеера. Нативную панель
субтитров платформы адаптер скрывает только пока активен наш показ.
## 3. Источники дорожек (адаптеры)

### 3.1 YouTube (основной, этап M3)

YouTube-плеер при загрузке страницы получает список дорожек субтитров
(`captionTracks` в player-ответе, тот же источник, из которого плеер берёт субтитры
сам). Адаптер читает этот список в контексте страницы и запрашивает cue-данные:

- **оригинал**: дорожка исходного языка видео (или любая выбранная);
- **перевод**: та же дорожка с параметром перевода (`tlang`) — YouTube отдаёт
  машинный перевод субтитров, если он доступен для пары языков.

Для многоязычного набора адаптер отдаёт **полный список** доступных языков (включая
несколько машинных переводов через `tlang`), и пользователь комбинирует любые 2–3
из них — например, `en (оригинал) + ru (tlang) + es (tlang)`. Порядок выбора задаёт
порядок строк на плашке.

Плюс резервный путь, если структура ответа изменится: чтение активных cue из
стандартного `<track>`-элемента/TextTrack API видеоэлемента. Оба пути версионируются
(см. §9).

Что не делаем: скачивание видео, обход ограничений, обращение к закрытым API.

### 3.2 Ручные файлы (универсальный, этап M3; реализовано — задача 3.6)

Drag&drop или кнопка «Свои субтитры» на любом сайте: файл `.srt`/`.vtt` парсится в
Rust-Core, cue-таблица возвращается в content-слой. Поддержка кодировок: UTF-8 (v1),
Windows-1251 — детект по BOM/эвристике (v1.1). Дорожка накладывается на любой `<video>`
найденного детектора. Свои файлы — полноценные участники набора: можно подгрузить
2–3 файла разных языков или смешать их с дорожками платформы и переводами (M4).
Дроп принимается, только когда на странице есть детектированное видео; прочие дропы
(например, загрузка файлов на сайт) проходят странице как без нас.

### 3.3 Прочие платформы (этап M6, карточки)

- **Vimeo**: TextTrack API плеера (public), адаптер по образцу YouTube.
- **Сайты с «голым» HTML5-видео**: ручные файлы (3.2) уже покрывают.
- **Платформы с DRM (Netflix и т.п.)**: вне скоупа v1 (см. docs/01 §4.3).
- **OCR субтитров из кадров** (для видео без дорожек): исследовательская карточка,
  после M6, только если запрос остаётся актуальным.

## 4. Синхронизация

Часы — только `video.currentTime` (единый источник правды, смена качества/seek не
рассинхронизируют показ):

1. подписка на `timeupdate` + `requestVideoFrameCallback` (если доступен) для
   покадровой точности;
2. активные cue всех дорожек набора ищутся бинарным поиском по отсортированному таймлайну
   (cue-таблицы предагрегированы: пересекающиеся интервалы смёржены);
3. сдвиг пользователя `offsetMs` применяется к обеим дорожкам (±10 с, шаг 100 мс,
   слайдер и горячие клавиши);
4. при смене скорости воспроизведения ничего specially не делаем — `currentTime`
   уже учитывает её.

Дрейф невозможен по построению (нет собственных часов). «Пропущенные» cue при резком
seek не показываются (порог: показывать cue, если до его конца ≥ 150 мс).

## 5. Оверлей (рендер)

- Контейнер: absolute-слой поверх видео, `pointer-events: none`, `z-index` выше
  контролов плеера (но ниже собственных панелей DuoPulse).
- Строк в блоке-«плашке» столько, сколько дорожек в наборе (1–3 в v1). Первая строка —
  оригинал (по умолчанию белый, 100% размера), вторая — перевод (фирменный лайм `#BDFE4F`,
  ~85% размера), третья и далее — ~75% размера с прозрачностью 75% (приглушённые).
  Цвета строк (оригинал/перевод/приглушённые) и подложки, обводка текста вкл/выкл —
  настраиваются (карточка duopulse-059): пресеты вида в панели «duo» (Фирменный /
  Ч/б контраст / Жёлтый TV), точные цвета — пипетки; всё — hex `#rrggbb` с клампами
  (`mergeStyle`), применение живое — строки перекрашиваются на месте, без пересоздания
  узлов. Пресеты обязаны читаться на светлом видео: обводка включена, подложка
  непрозрачнее ~0,7. Полупрозрачная подложка-градиент цвета подложки (дефолт —
  сине-чёрный) для читаемости на светлом видео.
- Позиция по умолчанию — низ по центру; регулируется (низ/верх, отступ).
- Размер шрифта: слайдер + колесо мыши по плашке (шаг 10%), от 75% до 300%; общий
  для всех строк набора, относительные размеры строк сохраняются.
- Авто-уменьшение кегля при переполнении (реализовано, карточка duopulse-046):
  если плашка сверх половины высоты видео (`PLATE_MAX_SHARE`), кегль плавно
  уменьшается пропорционально переполнению (итерации с замером), не ниже 75%
  (читаемость важнее доли); ручное колесо работает поверх — заданный масштаб
  база, авто его только ограничивает и не персистится.
- Анимация появления плашки — 80 мс fade (быстро, без «мигания» на коротких cue).
- Экономия: перерисовка только при смене активного набора cue (не на каждый кадр).

Стиль соответствует [06-brand-style.md](06-brand-style.md) («субтитры» — отдельный
раздел гайда).

## 6. Модель данных

```ts
interface Cue        { startMs: number; endMs: number; text: string }
interface Track      {
  id: string;            // "yt:en:orig"
  source: 'youtube' | 'file' | 'translate';
  lang: string;          // BCP-47
  role: 'original' | 'translation';
  cues: Cue[];           // отсортированы, смёржены
  videoKey: string;      // стабильный ключ видео (YouTube id / URL+duration)
}
interface SubtitlesState {
  enabled: boolean;
  tracks: Track[];      // упорядоченный набор, 1–3 в v1 (архитектурно — без предела);
                         // порядок = порядок строк на плашке; [] = показ выключен
  offsetMs: number;
  style: SubtitleStyle;  // размер, позиция, отступ, прозрачность, цвета строк и
                         // подложки, обводка (карточка duopulse-059)
}
interface SubtitleStyle {
  fontScalePct: number;            // 75–300, шаг 10
  position: 'bottom' | 'top';
  marginPct: number;               // отступ от края видео, 0–25
  plateOpacity: number;            // 0.2–1
  originalColor: string;           // hex #rrggbb — строка оригинала
  translationColor: string;        // строка перевода
  mutedColor: string;              // третья и далее (прозрачность 0.75 фиксирована)
  plateColor: string;              // подложка-градиент (база → прозрачный)
  textStroke: boolean;             // тёмная обводка 2px (гайд 06 §6)
}
```

SQLite-кэш (Core): `videoKey → {track meta, cues, translations}` — повторный просмотр
того же видео не ходит в сеть за теми же дорожками.

## 7. Перевод (этап M4)

Когда платформа не даёт перевод сама (или пользователь хочет другой язык):

- провайдеры (по порядку приоритета): 1) перевод самой платформы (YouTube `tlang`,
  бесплатно, для поддерживаемых пар); 2) облачный API по ключу пользователя
  (DeepL / Google Translate / OpenAI-совместимый); 3) self-hosted LibreTranslate;
- батчинг: cue группируются пачками ≤ 2 КБ текста, контекст = предыдущая пачка
  (для связности терминов);
- кэш: `(videoKey, trackId, targetLang, provider) → cues` в SQLite, LRU-очистка;
- деградация: нет сети/ключа → перевод из кэша, чего нет — показываем оригинал
  и бейдж «перевод недоступен», никаких крашей и блокировок просмотра;
- приватность: наружу уходят только тексты субтитров (см. docs/02 §9).

Интерфейс провайдеров реализован в задаче 4.1 (`src-tauri/src/translate/`):
trait с лимитами пачки и типизированными ошибками (ретраи — сетевые/429/5xx),
реализации DeepL / Google Translate v2 / LibreTranslate; выбор провайдера —
секция «Перевод» панели субтитров (ключ "translate" в settings.json), ключи
API — только DPAPI (`translate/keys/<provider>.bin`, по образцу пароля
прокси). Конвейер реализован в задаче 4.2 (`src-tauri/src/translate/
pipeline.rs` + `src-tauri/src/subtitles/cache.rs`): команда
`subtitles.translate_track` (источник — дорожка из набора, по умолчанию
оригинал) → cues едут в Core WebMessage'м → пачки ≤ 2 КБ с контекстом →
кэш → переведённая дорожка `cloud:<lang>` в наборе; прогресс — событие
`subtitles:translate_progress`, панель показывает «Перевод… 12/40» и итог;
селект «+ перевод в… (облако)» исключает языки платформы (бесплатный tlang
приоритетнее) и языки набора. Деградация с бейджем «перевод недоступен» —
задача 4.3 (`src-tauri/src/translate/watcher.rs`): очередь работ дедуплицирует
запросы по (videoKey, trackId, targetLang) — повторный запрос того же языка,
пока конвейер жив, переподчиняет ответ; сетевой отказ → бейдж
(событие `subtitles:translate_unavailable`, offline/willRetry) + автоповтор
— TCP-проба эндпоинта текущего провайдера каждые 5 с
(`DUOPULSE_TRANSLATE_RETRY_MS`), провайдер пересобирается на каждой попытке
(настройки могли смениться, пока ждали сеть); выключенный конвейер или
отсутствующий ключ — бейдж no_provider без автоповтора (подсказка панели);
набор живёт с оригиналом и кэшем, кэш-хит работает и без сети; работа
снимается, когда вкладка ушла с видео. OpenAI-совместимый провайдер —
кандидат на добавление по карточке-пожеланию.

## 8. UI-точки входа

1. Кнопка «duo» в адресной строке (реализовано в 3.7; состояние: выкл / одна
   дорожка / дуо / три — индикатор-точки и неон-кромка при активном показе) —
   видна на любой странице, где детектор нашёл видео (карточка duopulse-057:
   и без дорожек платформы — панель даёт свои файлы .srt/.vtt, облачный
   перевод и стиль плашки; пустой набор честно отражается в панели). Клик —
   панель (п.3); состояние обновляется событием `subtitles:set_applied`
   активной вкладки.
2. Горячая клавиша `Alt+D` — включить/выключить субтитры (последний набор;
   реализовано в 3.7). Ловится и в контентной вкладке (поглощает клавишу), и
   в хроме (IPC `subtitles.toggle`); вслед за переключением панель
   открывается/закрывается. Включение на пустом наборе собирает дефолт
   «оригинал + предпочитаемый перевод» (ru → uk → en, content/set-defaults) —
   сценарий §5.1 «Alt+D на свежей лекции даёт дуо en+ru».
3. Панель настроек субтитров (реализовано в 3.7, `src/subtitles-panel/`;
   снапшот — IPC `subtitles.list_tracks`, применение — `set_tracks` /
   `set_enabled` / `remove_track` / `set_style`): состав набора — пресеты
   (Оригинал / Дуо / Трио из списка адаптера), добавление дорожек (язык
   платформы или перевод), удаление, порядок строк (↑/↓ — перестановка без
   перезагрузки дорожек); размер, позиция, сдвиг. Вид плашки (карточка
   duopulse-059): чипы пресетов вида — Фирменный / Ч/б контраст / Жёлтый TV /
   Свои (подсветка активного по совпадению цветов+обводки+прозрачности),
   пипетки цветов строк и подложки, тумблер «Обводка»; применение живое
   (патч `set_style` перекрашивает строки оверлея на месте, без перезагрузки
   страницы; снапшот возвращается событием `subtitles:set_applied`).
   Дефолтный вид для новых вкладок задаётся на странице настроек
   (`settings.apply` → initialization-скрипт `__DUOPULSE_DEFAULTS__`).
   Перевод — реализовано в
   4.1–4.3: секция «Перевод» (провайдер DeepL/Google/LibreTranslate, ключ —
   DPAPI) и селект «+ перевод в… (облако)» — дорожка `cloud:<lang>`
   переводится конвейером Core (§7), статус — «Перевод… 12/40» и итог
   (кэш/сеть/ошибка); офлайн/нет провайдера — бейдж «Перевод недоступен»
   (4.3: держится, пока Core ждёт сеть для автоповтора).
   «Свои субтитры…» — нативный выбор файла (плагин dialog) → `subtitles.load_file`.
4. Колесо мыши по плашке субтитров — размер (с зажатым Shift — сдвиг).
5. Сдвиг синхронизации (реализовано в 3.5): `Alt+[` — раньше, `Alt+]` — позже
   (шаг 100 мс, работают при активном наборе); каждое изменение сдвига —
   колесом, клавишами, слайдером или командой `subtitles.set_offset` —
   открывает HUD с индикацией («+0,3 с») и слайдером ±10 с (автоскрытие
   ~2,4 с простоя); слайдер панели настроек задаёт тот же offset.
6. Drag&drop ручных файлов (реализовано в 3.6): 1–3 файла `.srt`/`.vtt` на
   страницу с видео (любой сайт); новый дроп замещает файловую часть набора
   целиком, файлы смешиваются с дорожками платформы (порядок строк: платформа,
   затем файлы). Кнопка «Свои субтитры» панели настроек — команда
   `subtitles.load_file` (файл с диска, тот же набор).

## 9. Живучесть против изменений платформ (главный риск фичи)

- Все знания о DOM/структурах YouTube — только внутри `adapters/youtube.ts`,
  остальные модули работают с абстракцией `Track`.
- Адаптер возвращает `version` и список «путей добычи» (primary → fallback → last resort).
  Пробует по очереди; в телеметрию (локальный журнал) пишет, какой путь сработал.
- Тесты на записанных фикстурах реальных страниц (снапшоты player-ответа) гоняются
  в CI на каждый коммит; падение = карточка «адаптер сломан» с приоритетом 0.
- Ручные файлы (3.2) остаются рабочим путём всегда — фича не «умирает» целиком.

## 10. Открытые вопросы (закрыты на M3 — карточка duopulse-029, 17.10.2026)

- **Оригинал при более длинном переводе — вариант B (адаптивная высота),
  реализовано (3.4).** Строки набора — независимые элементы: каждая переносится
  своим текстом (`white-space: pre-wrap`), плашка растёт вниз/вверх ровно под
  контент, фиксированные высоты (вариант A) не используются. Текст центрирован
  (гайд 06 §6), перенос — внутри строки (задача 3.4).
- **Компоновка трёх строк: перенос длинных cue и авто-уменьшение кегля при
  переполнении — реализованы (3.4 + карточка duopulse-046).** Плашка растёт с
  контентом (≤ 80% ширины видео, гайд 06 §6), каждая строка переносится своим
  текстом (`white-space: pre-wrap`); при выходе за половину высоты видео кегль
  плавно уменьшается под потолок (не ниже 75%), ручной масштаб колесом работает
  поверх; кегль масштабируется с плеером (cqw) и настраивается колесом (75–300%).
- **Автовыбор набора по умолчанию — реализован (3.7).** Alt+D на пустом наборе
  собирает «оригинал + предпочитаемый перевод» (ru → uk → en,
  `content/set-defaults.ts`), по ручному тестированию сценарий §5.1
  «Alt+D на свежей лекции даёт дуо en+ru» проходит (e2e/youtube §5.1);
  телеметрия не собирается — сознательно.
- **Полноэкранный и театральный режимы — реализованы (3.4).** Геометрия плашки
  следует за CSS-боксом видео (`resize`/`scroll`/`fullscreenchange` +
  ResizeObserver), кегль масштабируется с шириной плеера (`clamp` в cqw);
  формат плашки един — отдельного полноэкранного вида нет.
