## 1. Конфигурация вывода Windows (факты, не настройка «на глаз»)

- WASAPI shared mix format устройства по умолчанию (все 3 роли: console/multimedia/communications):
  **2 канала, 48000 Гц, 32 бит, channel mask 0x3 (стерео)** — измерено напрямую
  `IMMDeviceEnumerator::GetDefaultAudioEndpoint` + `IAudioClient::GetMixFormat` (`_tmp/wasapi-check.ps1`).
- Активные эндпоинты (`Get-PnpDevice -Class AudioEndpoint`, state=ACTIVE):
  - **Speakers (Realtek(R) Audio)** — встроенные динамики ноутбука; `PKEY_AudioEndpoint_PhysicalSpeakers`
    содержит WAVEFORMATEXTENSIBLE **2 ch, mask 0x3** (реестр MMDevices);
  - **Speakers (NoMachine Microphone Adapter)** — виртуальный удалённый вывод, тоже **2 ch, mask 0x3**.
- **NVIDIA High Definition Audio (HDMI) — NOTPRESENT**: ТВ/ресивер не подключён
  (в истории MMDevices числится Philips 42PFL3604H по HDMI — сейчас отключён).
- Итог: настроить Windows на 5.1/7.1 и пройти поканальный тест ОС на этой машине
  **физически невозможно** — нет ни одного устройства с >2 каналами вывода.
  Realtek-аудиовход ноутбука поддерживает только стерео-динамики.

## 2. Стенд (готов к повторному использованию)

- `e2e/m0-audio/generate-assets.ps1` — генератор тест-файлов: SAPI-TTS (Microsoft David, en-US)
  проговаривает метку каждого канала («Front Left», «Center», …) поверх опорного тона своей частоты;
  ffmpeg собирает файлы, где у канала своё 2-секундное окно, вне окна — цифровая тишина.
- `e2e/m0-audio/assets/` — 8 файлов: `test-2.0.wav`, `test-5.1.wav`, `test-7.1.wav` (PCM,
  WAVE_FORMAT_EXTENSIBLE, маски 5.1/7.1), `test-5.1.flac`, `test-5.1.opus.ogg`,
  `test-5.1-aac.mp4`, `test-7.1-aac.mp4`, `test-5.1-ac3.mp4` (H.264-видео с подписью активного канала).
  Контроль изоляции (ffprobe/astats): в своём окне RMS ≈ −22 дБ, в чужих — тишина.
- `e2e/m0-audio/audio-test.html` — страница-стенд: (1) блок окружения WebAudio,
  (2) тихий автотест: `<audio>`/`<video>` → MediaElementAudioSource → ChannelSplitter →
  AnalyserNode×8, пик каждого канала в своём и чужих окнах, выход заглушен Gain(0);
  (3) обычные элементы для прослушивания человеком; (4) «соло канала» через WebAudio.
  Результаты дублируются в `window.__AUDIO_TEST_RESULTS__` для CDP.
- `e2e/m0-audio/serve.mjs` — статический сервер стенда (`http://127.0.0.1:8788`).
- `src-tauri/src/main.rs` — добавлен `DUOPULSE_START_URL`: стартовая страница content-webview
  переопределяется переменной окружения (использовано этим стендом, пригодится будущим e2e).

Запуск: `node e2e/m0-audio/serve.mjs`, затем
`DUOPULSE_START_URL=http://127.0.0.1:8788/audio-test.html WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9222 npm run tauri dev`.

## 3. Автотест декодера/пайплайна в спайке (WebView2, Edge/154)

Окружение, которое видит страница: `destination.channelCount=2, channelCountMode=explicit,
maxChannelCount=2` — корректно отражает стерео-устройство ОС (совпадает с §1);
`AudioContext({channelCount:6})` создаётся без ошибок, но destination остаётся 2-канальным
(следует за устройством — механизм отвечает конфигурации ОС, что и требуется по F-11).

Каждый канал: пик в **своём** окне ≥ −42 дБ и в **чужих** ≤ −56 дБ (по факту — полная тишина).

## 5. YouTube: ролик «Dolby Atmos 5.1 Surround Sound Test» (watch?v=iTHtXgnhqfM)

Метод: в контексте страницы прочитаны `ytInitialPlayerResponse.streamingData.adaptiveFormats`,
затем к живому `<video>` подключён WebAudio-зонд (MediaElementSource → Splitter → Analyser×8),
измерены пики каналов во время воспроизведения.

- Форматы, отданные **web-клиенту** (одинаково в спайке и Edge):
  стерео — itag 140 (mp4a 130k), 249/250/251 (Opus);
  **6-канальные — itag 256 (`mp4a.40.5` AAC 5.1), 258 (`mp4a.40.2` AAC 5.1), 328 (`ec-3`), 380 (`ac-3`)**.
  `player.getAvailableAudioTracks()` → `[]` (переключателя «5.1» web-плеер не отдаёт).
- Живой замер: **спайк** — ch0 −2.8 дБ, ch1 −2.9 дБ, ch2…ch7 −∞ (повторный прогон −5.1/−6.2 дБ);
  **Edge** — ch0 −3.4 дБ, ch1 −3.5 дБ, ch2…ch7 −∞.
- Вывод: web-плеер YouTube **выбирает стерео-дорожку**, даже когда 6ch AAC лежит рядом в манифесте;
  AC-3/EAC-3 в Chromium не декодируются вовсе. Это поведение платформы YouTube для web-клиентов
  (официально 5.1 — для ТВ-приложений: support.google.com/youtube/answer/11904456), а не дефект
  WebView2: **в спайке ровно то же, что в Edge/Chrome на этой машине — «не хуже» подтверждено**.
- Скриншоты с оверлеем-зондом: `audio-youtube-51-spike.png` (спайк, видео на паузе после замера),
  `audio-youtube-51-edge.png` (Edge).

## 6. Что осталось до полного закрытия F-11 (после появления железа)

1. Подключить к машине выход ≥5.1 (HDMI-ТВ/ресивер к NVIDIA HDMI — путь уже известен,
   в MMDevices числится Philips 42PFL3604H — или USB/аналоговый 5.1-выход).
2. Настроить Windows: «Настроить динамики» → 5.1, затем 7.1; поканальный тест ОС должен проходить.
3. Открыть стенд (§2) и выполнить разделы 3 («Прослушивание») и 4 («Соло канала») на слух:
   каждая метка — из своего динамика. Автотест (раздел 2) при этом покажет
   `maxChannelCount` = 6/8 — страница печатает это автоматически.
4. YouTube: сравнить громкость/панораму с Edge на той же машине (ожидаемо одинаково-стерео,
   см. §5); для настоящего 5.1 с YouTube в браузере нет пути ни в одном Chromium —
   при желании отдельной карточкой рассмотреть TV-клиентский InnerTube-путь (вне скоупа v1).
