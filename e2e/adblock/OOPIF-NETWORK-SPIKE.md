# Спайк duopulse-190: сетевой уровень для кросс-доменных (OOPIF) фреймов WebView2

Дата: 20.11.2026. Рантайм на стенде: WebView2 157.0.4341.60, webview2-com 0.39.1
(объявляет ICoreWebView2_22). Контекст: карточки duopulse-188/190 — WebView2 не
поднимал WebResourceRequested для запросов out-of-process фреймов, реклама
плеер-iframe (cinemar.cc) уходила с HTTP 200 мимо движка даже под EasyList.

## Что проверено и чем закончилось

| № | Путь | Результат (замер e2e/adblock/frame-storm-probe.mjs, 42 фрейма) |
|---|-----|-----------------------------------------------------------------|
| 1 | Базовая регистрация `AddWebResourceRequestedFilter("*", ALL)` | **Не работает**: событие для OOPIF-запросов не поднимается — перехватывался только same-origin фрейм (1/42 блокирован; контрольные: `127.0.0.1`-фрейм 403, `localhost`-фрейм 200) |
| 2 | Браузер-флаг `msEdgeWebViewApplyWebResourceRequestedFilterForOOPIFs` + базовая регистрация (docs «WebView2 browser flags») | **Не работает на рантайме 157**: 41/42 проходили насквозь (blocked=1). Флаг в чистом виде пробел не закрывает |
| 3 | Перегрузка **`ICoreWebView2_22::AddWebResourceRequestedFilterWithRequestSourceKinds("*", ALL, REQUEST_SOURCE_KINDS_ALL)`** | **Работает**: 42/42 фреймовых запросов перехвачено (контрольные `localhost`-фрейм → 403). РАБОТАЕТ БЕЗ браузер-флага (проверено A/B) |
| 4 | Флаг + перегрузка | Работает, флаг избыточен — из кода удалён (нестабильные browser-flags в продакшене держать незачем) |
| 5 | Service Worker-инъекция в origin фрейма | **Неприменимо**: регистрация SW требует same-origin https-скрипта — у третьестороннего фрейма такой страницы нет |
| 6 | Локальный прокси-режим (как роутер мобильной ветки) | Не понадобился: перегрузка решает пробел внутри WebView2 без MITM/TLS-осложнений |

A/B-доказательство: `DUOPULSE_OOPIF_FILTER=0 node e2e/adblock/frame-storm-probe.mjs`
(выключатель в main.rs переводит регистрацию на базовую) — та же страница, тот же
fetch из фрейма: blocked=1/passed=41. Разница только в способе регистрации фильтра.

## Что внедрено (итог карточки 190)

1. **Сеть**: `install_request_blocker` (src-tauri/src/main.rs) регистрирует фильтр
   перегрузкой с `REQUEST_SOURCE_KINDS_ALL` (рантайм без ICoreWebView2_22 — тихий
   фолбэк на базовую регистрацию, фреймы снова мимо, но ничего не ломается).
   Следствие: сетевые правила и `$replace` (общий хендлер) теперь действуют и во
   фреймах. Живое подтверждение — sites-ads-probe: blockedTotal вырос 4 → 17
   (движок начал резать запросы внутри плеер-фрейма uakinogo).
2. **Скриптлеты во все фреймы** (гейт `FRAME_SCRIPTLET_HOSTS` снят, согласовано с
   Артёмом: «расширить на все фреймы с префильтром»): решение
   `AdblockService::frame_script_plan` — дешёвый префильтр «есть ли у хоста хоть
   какие-то правила» (разбор текстов списков: `||host`, `@@||`, `host##…`,
   entity `example.*`; суффикс-матчинг по меткам, O(меток) ≈ 6 мкс) + кэш по
   хостнейму (результат `url_cosmetic_resources` — функция хоста; шторм уникальных
   URL рекламных фреймов гасится) + дедупликация in-flight расчётов.

## Замеры перфа (критерий «перф-деградации нет»)

- `cargo test frame_perf_probe -- --ignored` (живой ансамбль списков, 89 027 строк,
  60 175 хостов в префильтре): полный расчёт `url_cosmetic_resources` —
  0,37–0,4 мс/URL на «неизвестных» хостах, 1,2 мс худший (youtube, первый вызов);
  префильтр — ~6 мкс/URL (≈70× дешевле; мемо-кэш повторов — 0).
  Исторические «0,2–0,9 с» (карточка 044) — это generic-фаза по DOM
  (`cosmetic_generic_selectors`, тысячи классов/идов страницы): во фреймовом
  пути она не вызывается.
- Фрейм-шторм (frame-storm-probe, 40 уникальных кросс-доменных хостов без
  правил + 2 контрольных): UI/Core round-trip 3 мс (UI-нить не подвисает),
  CPU дерева после загрузки +0,4 с за 10 с наблюдения — фон-шторма расчётов
  нет (префильтр отсекает до движка).

## Ограничения / наследие

- Старый рантайм (< SDK 1.0.2957, без ICoreWebView2_22): фолбэк — фреймы мимо
  сетевого уровня (как до 190), скриптлеты и префильтр работают независимо.
- Дом-прероллы с origin самого плеера (cinemar.cc крутит свою казино-рекламу
  через MSE blob, если VAST-теги порезаны) сетевыми правилами не убираются —
  это тот же origin, что и плеер; отдача 20.11: uakinogo сменил сеть Epom →
  traffer/temptcdn (закрыто в duopulse-sites, sites.txt), дом-слоты остались
  (фильм стартует после них, стенд ждёт конца «Рекламы» и кликает).
- Браузер-флаг `msEdgeWebViewApplyWebResourceRequestedFilterForOOPIFs` на
  рантайме 157 бесполезен без перегрузки — если Microsoft сменит поведение,
  A/B-стенд это покажет (проверка 2 инвертируется).
