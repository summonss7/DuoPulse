# duopulse-060 · ASR-спайк: протокол замеров (29.10.2026)

Исследовательская карточка CARDS/060: субтитры для видео без дорожек — генерация
ASR. Прототипы и замеры выполнены вне приложения, в `%TEMP%\duopulse-asr-proto`
(машина автора; модели >700 МБ и тест-аудио в репо не хранятся — п. «воспроизведение»).

## 1. Вопросы спайка

1. Скорость локального ASR (whisper.cpp) на эталонной машине — реально ли
   перекодировать ролик 10–30 мин за приемлемое время (RTF = сек аудио / сек счёта).
2. Качество по языкам (en — чистая синтетическая речь SAPI; ru — живая начитка
   LibriVox, проза XIX века) в зависимости от размера модели.
3. Альтернатива: Vosk (маленькие модели, онлайн-стриминг).
4. Вес: размер моделей/зависимостей в поставке.
5. Доступность аудиопотока YouTube для Core (см. §5).
6. Облачные альтернативы и цены (§6).

## 2. Материалы

- Движок: whisper.cpp master 284029c (28.10.2026), сборка cmake+ninja,
  GNU-тулчейн D:\tools\mingw64 (gcc 16.2), 8 нитей CPU; CLI `whisper-cli.exe`.
  В сборке присутствует и `whisper-server.exe` (OpenAI-совместимый HTTP-API) и
  `parakeet-cli.exe` (NVIDIA Parakeet, en/многоязычный v3 — не тестировался).
- Vosk: python 3.13 + pip vosk; модели small-en-us-0.15 (40 МБ) и small-ru-0.22 (45 МБ).
- Тест-аудио (все 16 кГц моно s16le):
  - `en_david` 79,5 с — Microsoft David (SAPI TTS), 203 слова: новости/техника/числа;
    ground truth = скрипт TTS (`gen-en-tts.ps1`).
  - `en_zira` 71,7 с — Microsoft Zira, 194 слова: погода/город/культура; там же.
  - `ru_belkin` 150,0 с — фрагмент аудиокниги LibriVox «Повести покойного
    Ивана Петровича Белкина» (belkintales_1406, общественное достояние), живой
    мужской голос, начинается словами «Считали его стариком…»; эталон — текст
    Wikisource, фрагмент выравнивается по первым словам гипотезы (читатель
    отклоняется от издания — WER ru завышён абсолютным уровнем, но сравнение
    моделей корректно).
- WER: ливиджин по словам, токенизация NFKC+нижний регистр, пунктуация долой,
  ё→е (`compute-wer.py`).

| Модель | en_david | en_zira | ru_belkin |
|---|---|---|---|
| whisper tiny | 7,4 % | 4,1 % | 39,1 % |
| whisper base | 7,9 % | 3,1 % | 28,4 % |
| whisper small | 7,9 % | 3,1 % | 13,8 % |
| vosk small | 2,5 % | 5,2 % | 31,0 % |

Выводы по качеству:
- en: все whisper-размеры достаточны для субтитров (WER 3–8 % на чистой речи);
  vosk-en сопоставим.
- ru: качество резко зависит от модели — tiny непригоден (39 %), base читаем
  (28 %), small хорош (14 %; с поправкой на несовпадение издания с эталоном —
  реальные ошибки ниже). Vosk-ru ≈ whisper-base.
- Рекомендуемый диапазон для субтитров: base (компромисс) или small (качество
  ru). Квантованные ggml (`*-q5_1`) в ~2,6× меньше (base ~58 МБ, small ~181 МБ)
  при малой потере качества — не замерялись, кандидат на проверку при реализации.

Методическая ошибка утреннего прогона (исправлена): whisper-cli с флагом `-nt`
(no timestamps) на части файлов терял середину и галлюцинировал (en_zira все
размеры, ru base — обрыв на трети); дефолтный вывод сегментами корректен.
Все числа выше — прогон без `-nt` (`run-whisper2.py`, транскрипты `w2_*`).

## 5. Аудио YouTube для Core (feasibility)

- Серверный innertube из Core отвергается платформой: WEB-клиент без браузерного
  контекста — `UNPLAYABLE` («Video unavailable»), ANDROID-клиент — HTTP 400
  (аттестация). Проверено curl'ом 29.10.2026 (player_web.json / player_android.json).
- Рабочие пути (оба внутри легитимной сессии страницы, как у captions-адаптера):
  1. Player response в контексте страницы: адаптер уже читает
     `movie_player.getPlayerResponse()` / `ytInitialPlayerResponse` для
     captionTracks (content/adapters/youtube.ts) — там же лежит
     `streamingData.adaptiveFormats` (аудио-итаги 139/140/251, m4a/webm).
  2. Перехват живых URL: сетевой COM-слой видит все googlevideo/videoplayback
     запросы плеера (с токенами); Core может повторить URL самофетчем через
     SOCKS5-роутер — прецедент `adblock/replace.rs` (ureq 2 + Proxy socks5).
- Риск реализации: direct fetch аудио-URL может требовать pot-токен сессии
  (как timedtext); путь 2 это снимает — URL уже «живой». Декод m4a/opus в Rust —
  symphonia (чистый Rust, без ffmpeg в поставке), ресемпл 16 кГц моно.
- Прочие сайты v1: «голое» `<video src>` (mp4/webm) — fetch src тем же самофетчем;
  MSE-плееры вне YouTube — вне скоупа v1.

## 6. Облачные ASR (цены на 29.10.2026, проверить при реализации)

| Провайдер | Модель | Цена/час аудио | Прим. |
|---|---|---|---|
| Groq | whisper-large-v3-turbo | $0,04 (~$0,0007/мин) | LPU, сотни × real-time; файл ≤25 МБ (free) / 100 МБ (dev); OpenAI-совместимый API; verbose_json с сегментами/словами |
| OpenAI | gpt-4o-transcribe / whisper-1 | $0,36 ($0,006/мин) | mini $0,18/час; файл ≤25 МБ |
| Deepgram | Nova-3 | ~$0,26–0,43 | стриминг, диаризация (не проверялось) |

Ключевое: у Groq/OpenAI API-форма одинакова (multipart /audio/transcriptions),
а whisper.cpp умеет поднимать `whisper-server` с тем же OpenAI-совместимым
эндпоинтом локально ⇒ один провайдер «OpenAI-совместимый ASR» (base URL + ключ
в DPAPI, по образцу translate-провайдеров) покрывает облако И локальный гибрид.

## 8. Воспроизведение

Скрипты: `gen-en-tts.ps1` (SAPI en-аудио + эталоны), `run-whisper2.py` (прогоны
whisper без `-nt`), `run-vosk.py` (Vosk), `compute-wer.py` (WER + ru-выравнивание);
исходники результатов — `results/` (JSON + транскрипты). Модели —
huggingface.co/ggerganov/whisper.cpp (ggml-{tiny,base,small}.bin); vosk —
alphacephei.com. ru-аудио: archive.org `belkintales_1406` (LibriVox), фрагмент
150 с «Считали его стариком…»; эталон — Wikisource «Выстрел». Пути в скриптах —
`%TEMP%\duopulse-asr-proto` (замещается при запуске). Транскрипты `w_*` —
ошибочный утренний прогон с `-nt`, оставлен для истории; правильные — `w2_*`.
